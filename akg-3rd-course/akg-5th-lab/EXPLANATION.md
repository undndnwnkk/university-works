# ЛР-5 по АКГ простыми словами: «Формирование изображения методом трассировки путей»

> Ключевые слова, которые должны быть в лабе: **треугольники**, **ускоряющая структура**, **готовая библиотека трассировки**.
> У нас: сцена состоит только из треугольников, своя ускоряющая структура — **BVH** (дерево ограничивающих
> объёмов, построенное по **SAH**), готовая библиотека — **Intel Embree** (через Python-пакет `embreex`).

---

## 0. Что сделано в одном абзаце

Есть трёхмерная сцена из треугольников (комната со стенами, зеркальный параллелепипед, стеклянная сфера,
пластиковый «узел», загруженный из OBJ-файла). Есть камера-точка и экран из пикселей. Из камеры через
каждый пиксель выпускаем луч, ищем, в какой треугольник он попал первым, и считаем, сколько света
приходит из этой точки в камеру: от каждого источника света (если источник не закрыт — **тень**),
плюс то, что приходит по зеркально отражённому и преломлённому лучу (их трассируем дальше, рекурсивно).
Получаем изображение в **абсолютных яркостях** (Вт/(ср·м²)), переводим в относительные (нормировка),
обрезаем всё, что больше 1, делаем **гамма-коррекцию** (γ = 2.2), переводим в 0–255 и пишем файл **PPM**.
Чтобы искать пересечения быстро, используем **ускоряющую структуру BVH** (своя реализация) или
**Embree** (готовая библиотека). Корректность доказываем: (1) сравнением с аналитическими формулами,
(2) сравнением трёх способов поиска пересечений между собой, (3) аналитической проверкой теней и законов оптики.

## 1. Самые главные термины (то, что спросят почти наверняка)

### 1.1. Трассировка лучей и путей

| Термин | Простыми словами |
|---|---|
| **Луч** | Полупрямая: точка начала `o` и направление `d` (единичный вектор). Точка на луче: `p(t) = o + t·d`, `t > 0` — расстояние. |
| **Прямая трассировка** | Лучи идут **от источника света** к объектам и, возможно, в камеру. Честно, но почти все лучи пролетают мимо камеры — очень дорого. |
| **Обратная трассировка** (backward ray tracing) | Лучи идут **из камеры** через пиксели в сцену — «в обратную сторону» по отношению к свету. Считаем только то, что реально видно. Это наш метод. |
| **Трассировка путей** (path tracing) | Луч из камеры отражается/преломляется несколько раз; цепочка отрезков — это **путь**. На каждой вершине пути считаем вклад источников. У нас два режима: `split` (луч разветвляется и на отражённый, и на преломлённый — «классическая» схема Уиттеда) и `path` (на каждой вершине **случайно** выбираем одно продолжение с вероятностью, пропорциональной коэффициенту, и делим вес на эту вероятность — это и есть «путь», метод Монте-Карло). |
| **Первичный луч** | Луч из камеры через пиксель. |
| **Теневой луч** (shadow ray) | Луч из точки поверхности к источнику света. Если по дороге есть препятствие — точка в **тени** от этого источника. |
| **Вторичный луч** | Отражённый (зеркально) или преломлённый луч, который запускаем из точки попадания дальше. |
| **Глубина трассировки** (`max_depth`) | Сколько раз максимум луч может отразиться/преломиться. Нужна, чтобы два зеркала друг напротив друга не дали бесконечную рекурсию. |
| **Пересечение луч–сцена** | Найти **ближайший** треугольник, в который попадает луч (минимальное `t > 0`). Самая дорогая операция — ради неё и нужна ускоряющая структура. |
| **Локальное освещение** | Учитываем свет, пришедший в точку **прямо от источников** (+ идеальное зеркальное отражение/преломление). Свет, рассеянный другими диффузными поверхностями (вторичная диффузная подсветка), **не** учитываем — это глобальное освещение, в задании его нет. |

### 1.2. Геометрия: треугольники

| Термин | Простыми словами |
|---|---|
| **Треугольная сетка** (mesh) | Любая поверхность представлена набором треугольников. Плоскость — 2 треугольника, куб — 12, сфера — тысячи. Почему треугольники: любой многоугольник на них разбивается, треугольник всегда плоский, пересечение с лучом считается очень быстро. |
| **OBJ-файл** | Простой текстовый формат: строки `v x y z` — вершины, `f a b c` — грани (номера вершин, с единицы). Наш «узел» лежит в `models/knot.obj` (19 200 треугольников) и загружается функцией `load_obj`. Многоугольники в `f` режем «веером» на треугольники. |
| **Нормаль** | Единичный вектор, перпендикулярный поверхности. Для треугольника: `n = normalize((v1−v0) × (v2−v0))`. |
| **Сглаженные нормали** (`smooth`) | Сфера из треугольников «гранёная». Чтобы она выглядела гладкой, в каждой вершине считаем среднюю нормаль соседних граней, а в точке попадания интерполируем эти нормали барицентрическими координатами (это **затенение по Фонгу** — интерполяция нормалей, не путать с моделью отражения Фонга). |
| **Барицентрические координаты** `(u, v)` | Любая точка треугольника: `p = (1−u−v)·v0 + u·v1 + v·v2`, где `u ≥ 0, v ≥ 0, u+v ≤ 1`. Если условие нарушено — точка вне треугольника. |
| **Алгоритм Мёллера–Трумбора** | Быстрый способ найти пересечение луча с треугольником: решаем систему `o + t·d = v0 + u·e1 + v·e2` (где `e1 = v1−v0`, `e2 = v2−v0`) правилом Крамера через векторные и скалярные произведения. Получаем сразу `t, u, v`. Функция `ray_triangle` в `accel.py`. |

Формулы Мёллера–Трумбора:

```
e1 = v1 − v0,  e2 = v2 − v0,  s = o − v0
P = d × e2,    det = e1 · P          (det ≈ 0 → луч параллелен плоскости, промах)
u = (s · P) / det                     (u ∉ [0,1] → промах)
Q = s × e1
v = (d · Q) / det                     (v < 0 или u + v > 1 → промах)
t = (e2 · Q) / det                    (t ≤ 0 → треугольник сзади, промах)
```

### 1.3. Ускоряющая структура (ОЧЕНЬ вероятный вопрос)

| Термин | Простыми словами |
|---|---|
| **Зачем** | Наивно: для каждого луча проверить **все** N треугольников → O(N) на луч. У нас 24 тыс. треугольников и десятки миллионов лучей → слишком медленно. Ускоряющая структура позволяет **сразу отбросить** большинство треугольников → примерно O(log N) на луч. |
| **AABB** (axis-aligned bounding box) | Параллелепипед со сторонами вдоль осей X, Y, Z, описанный вокруг группы треугольников. Задаётся двумя точками `min` и `max`. Пересечь луч с ним очень дёшево. |
| **Slab-тест** (тест «пластин») | Пересечение луча с AABB: для каждой оси находим `t` входа и выхода из «слоя» между двумя плоскостями: `t1 = (min − o)/d`, `t2 = (max − o)/d`. Вход в коробку `tn = max(min(t1,t2))` по трём осям, выход `tf = min(max(t1,t2))`. Попадание, если `tn ≤ tf` и `tf ≥ 0`. Функция `ray_box`. |
| **BVH** (Bounding Volume Hierarchy, иерархия ограничивающих объёмов) | **Двоичное дерево**: корень — коробка вокруг всей сцены, у каждого узла два ребёнка — коробки вокруг двух половин его треугольников. В **листьях** — несколько треугольников (у нас ≤ 4…16). Если луч не попал в коробку узла — **всё поддерево пропускается**. |
| **Построение BVH** | Рекурсивно делим множество треугольников на две части. Вопрос — **как** делить? |
| **SAH** (Surface Area Heuristic, эвристика площади поверхности) | Способ выбрать лучшее деление. Вероятность того, что случайный луч попадёт в дочернюю коробку, пропорциональна её **площади поверхности**. Стоимость разбиения: `C = C_trav + (S_L/S)·N_L·C_tri + (S_R/S)·N_R·C_tri`, где `S` — площадь коробки родителя, `S_L, S_R` — детей, `N_L, N_R` — число треугольников в детях. Перебираем все разрезы по каждой из трёх осей (треугольники отсортированы по центрам), берём минимум. Если делить невыгодно (стоимость ≥ N) — делаем лист. |
| **Обход BVH** | Стек узлов. Достаём узел; если коробка не пересечена или пересечена дальше уже найденного ближайшего попадания — пропускаем. Если лист — проверяем его треугольники. Иначе кладём в стек обоих детей, **ближнего последним** (чтобы проверить его первым: найдём близкое попадание и отсечём дальние узлы). Функция `bvh_intersect`. |
| **Поиск ближайшего** vs **любого** пересечения | Для первичных/вторичных лучей нужно **ближайшее** попадание (`intersect`). Для теневого луча достаточно знать, есть ли **хоть одно** препятствие до источника (`occluded`) — можно остановиться на первом найденном, это быстрее. |
| **Другие ускоряющие структуры** (на всякий) | Равномерная сетка (grid), октодерево (octree), k-d дерево (делит пространство плоскостями, а не объекты), BSP. BVH сейчас — стандарт (используется в Embree, OptiX, RTX-видеокартах). Отличие BVH от k-d: BVH делит **объекты** (коробки могут перекрываться, каждый треугольник ровно в одном листе), k-d делит **пространство** (ячейки не перекрываются, треугольник может попасть в несколько). |

### 1.4. Готовая библиотека трассировки

| Термин | Простыми словами |
|---|---|
| **Intel Embree** | Открытая библиотека Intel с очень быстрыми ядрами трассировки лучей на CPU (SIMD-инструкции SSE/AVX, многопоточность). Внутри — тоже BVH, только оптимизированная до предела. Используется в Blender Cycles, Corona, V-Ray и др. Задание прямо разрешает её использовать. |

| **Как у нас устроено** | Три взаимозаменяемых «бэкенда» с одинаковым интерфейсом `intersect` / `occluded`: `brute` (полный перебор — эталон), `bvh` (наша BVH, ускорена `numba`), `embree` (готовая библиотека). ### 1.5. Радиометрия (из лекции 1 — физические величины света)

| Величина | Обозначение, единицы | Простыми словами |
|---|---|---|
| **Энергия** | Q, Дж | Сколько всего энергии. |
| **Поток** (мощность) | Φ = dQ/dt, Вт | Энергия в секунду. |
| **Телесный угол** | ω, ср (стерадиан) | «Угол в 3D»: площадь пятна на единичной сфере. Вся сфера = 4π ср. Для площадки площади S на расстоянии R: ω ≈ S/R². |
| **Сила излучения** | I = dΦ/dω, Вт/ср | Сколько потока источник шлёт в единицу телесного угла в данном направлении. **Так задаются наши точечные источники** (`intensity`). |
| **Освещённость** (irradiance) | E = dΦ/dS, Вт/м² | Сколько потока **падает** на единицу площади. |
| **Светимость** (exitance) | M = dΦ/dS, Вт/м² | Сколько потока **уходит** с единицы площади. |
| **Яркость** (radiance) | L = d²Φ/(dω·dS·cosθ), Вт/(ср·м²) | **Главная величина.** Именно её «видит» камера/глаз, и она не меняется вдоль луча в вакууме. **Наше изображение — это яркость в каждом пикселе.** |

Ключевые формулы:

* **Закон обратных квадратов + косинус** (освещённость от точечного источника):
  `E = I(θ_ист) · cos θ_пов / R²`, где `R` — расстояние до источника, `θ_пов` — угол между нормалью и направлением на источник.
* **Ламбертовский источник** (диаграмма излучения «Ламберт», как требует задание):
  `I(θ) = I0 · cos θ`, где `θ` — угол между осью источника (`direction`) и направлением на точку.
  Источник светит сильнее всего вдоль оси и не светит вбок/назад. Яркость такой площадки одинакова со всех сторон.
* **Параллельный (направленный) источник** (типа Солнца): все лучи параллельны, задаётся освещённость
  `E0` на перпендикулярной площадке: `E = E0 · cos θ`. Расстояния нет, обратного квадрата нет.
* **Фотометрия** — то же самое, но взвешенное чувствительностью глаза V(λ): люмен вместо ватта, кандела
  (= лм/ср) вместо Вт/ср, люкс (= лм/м²) вместо Вт/м², нит (= кд/м²) вместо Вт/(ср·м²). Множитель 683 лм/Вт.

### 1.6. Как поверхность отражает свет: BRDF и модели (лекция 3)

| Термин | Простыми словами |
|---|---|
| **BRDF** f(ωi, ωo) | Двулучевая функция отражательной способности: какая доля света, пришедшего из направления ωi, уходит в направление ωo. `f = dL_out / dE_in`, единицы 1/ср. |
| **Уравнение рендеринга** (из лекции) | `Lo(p, ωo) = ∫ f(p, ωo, ωi) · Li(p, ωi) · cos θi dωi` — яркость, уходящая из точки, = сумма по всем входящим направлениям. |
| **Как оно упрощается у нас** | Свет приходит только от **точечных/параллельных** источников (интеграл превращается в сумму) + идеальные зеркальные направления: `Lo = Σ_источников f(ωi, ωo) · E_i · V_i + kr·L_отраж + kt·L_прелом`, где `V_i` = 0 или 1 — видимость (тень), `E_i` — освещённость от источника. |
| **Модель Ламберта** (идеально диффузная) | `f = kd / π`. Свет рассеивается равномерно во все стороны, поверхность выглядит одинаково яркой с любого угла (мел, бумага, матовая краска). Делим на π, чтобы при kd = 1 отражалась ровно вся энергия (закон сохранения). |
| **Модель Фонга** (блик) | Блик вокруг идеально отражённого направления: `R = 2(N·L)N − L`, `f_s = ks · (n+2)/(2π) · (R·V)^n`. `n` (shininess) — «блёсткость»: чем больше, тем меньше и ярче блик. |
| **Модель Блинна–Фонга** | Вместо отражённого вектора — **полувектор** `H = normalize(L + V)` (посередине между направлением на свет и на наблюдателя): `f_s = ks · (n+8)/(8π) · (N·H)^n`. Считается проще, на скользящих углах выглядит реалистичнее. При одинаковом `n` блик Блинна–Фонга **шире**, чем у Фонга (угол между N и H примерно вдвое меньше угла между R и V). |
| **Нормировочные множители** `(n+2)/2π`, `(n+8)/8π` | Чтобы при изменении `n` общая отражённая энергия не менялась (блик становится уже, но ярче). Это «физически правдоподобная» (нормированная) форма моделей. |
| **Кук–Торранс** | Физически обоснованная микрогранная модель (распределение микрограней D, затенение G, Френель F). В задании «одна из: Кук–Торранс, Фонг, Блинн–Фонг» — мы сделали **две**: Фонга и Блинна–Фонга (`"model": "phong"` / `"blinn"`). |
| **Зеркальное отражение** (kr) | Идеальное зеркало: `R = D − 2(D·N)N`, «угол падения = угол отражения». Яркость по отражённому лучу умножаем на `kr`. |
| **Пропускание / преломление** (kt, ior) | Прозрачная среда с показателем преломления `n ≥ 1` (стекло 1.5, вода 1.33). Направление по **закону Снеллиуса**: `n1·sin θ1 = n2·sin θ2`. |
| **Полное внутреннее отражение (ПВО)** | При выходе из более плотной среды (стекло → воздух) при угле больше критического `θкр = arcsin(n2/n1)` (для стекла 41.8°) преломлённого луча нет — весь свет отражается. У нас тогда `kt` добавляется к отражению. |
| **Диффузное пропускание** (kdt) | Как матовая бумага/абажур: свет, падающий с **обратной** стороны, рассеивается по Ламберту: `f = kdt/π`. |
| **Закон сохранения энергии** | Поверхность не может отразить и пропустить больше, чем на неё упало: `kd + ks + kr + kt + kdt ≤ 1` (для каждого канала). Проверяется в `verify.py`. |

### 1.7. Цвет и вывод изображения (лекции 3–4)

| Термин | Простыми словами |
|---|---|
| **RGB-модель** | Цвет — три числа (красный, зелёный, синий). Все коэффициенты и источники у нас RGB-тройки, расчёт идёт независимо по трём каналам. Задание разрешает «спектральная или RGB». |
| **Спектральная модель** | Вместо 3 чисел — значения на многих длинах волн (380–780 нм). Точнее (дисперсия, метамерия), но дороже. Мы делали её в ЛР-3/4. |
| **Абсолютные яркости** | То, что насчитал трассировщик: числа в Вт/(ср·м²), могут быть от 0 до чего угодно. На мониторе так показать нельзя. |
| **Нормировка** (перевод в относительные яркости) | Делим всё изображение на одно число: на **максимальную** яркость (`max`), так, чтобы **средняя** яркость стала 0.5 (`mean`), или на **заданное** значение (`fixed`). Всё, что после деления > 1, **отсекается** до 1. |
| **Гамма-коррекция** | Монитор показывает яркость нелинейно (≈ V^2.2). Чтобы картинка выглядела правильно, перед записью делаем `V_corr = V^(1/γ)`, γ = 2.2. Тёмные значения «поднимаются»: 0.18 → 117 из 255, 0.5 → 186. |
| **Перевод в 0–255** | `round(V_corr · 255)` → байт на канал. |
| **PPM** (Portable PixMap) | Простейший формат: текстовый заголовок `P6\nширина высота\n255\n`, потом подряд байты R G B каждого пикселя. Пишется в 3 строки кода (`save_ppm`). Дополнительно сохраняем PNG для отчёта. |
| **Яркость Y** | `Y = 0.2126·R + 0.7152·G + 0.0722·B` — «насколько светлый» цвет для глаза (зелёный глаз чувствует сильнее всего). Используется в нормировке `mean`. |

### 1.8. Камера и антиалиасинг

| Термин | Простыми словами |
|---|---|
| **Точечная камера** (pinhole) | Все лучи выходят из одной точки (`position`). Экран — прямоугольник перед камерой на расстоянии 1, его размер задаётся углом обзора `fov`. |
| **Базис камеры** | `forward = normalize(look_at − position)`, `right = normalize(forward × up)`, `up' = right × forward`. |
| **Луч через пиксель (px, py)** | `x = (2·px/W − 1)·tan(fov/2)·W/H`, `y = (1 − 2·py/H)·tan(fov/2)`, `d = normalize(forward + x·right + y·up')`. |
| **Алиасинг** | «Лесенка» на краях объектов: один луч на пиксель — пиксель либо полностью «объект», либо «фон». |
| **Антиалиасинг (суперсэмплинг)** | Несколько лучей на пиксель (`spp` — samples per pixel), результаты усредняем. У нас **стратифицированный джиттер**: пиксель делится на k×k клеток (spp = k²), в каждой клетке случайная точка. Края получаются гладкими. |

## 2. Ход работы (что и в каком порядке делает программа)

1. **Чтение сцены** из JSON-файла (`scenes/*.json`): камера, настройки рендера, материалы, объекты, источники.
2. **Построение треугольной сетки** (`scene.py`): каждый объект превращается в треугольники:
   `quad` (2 треуг.), `box` (12), `sphere` (икосфера: икосаэдр, каждый треугольник делится на 4 и вершины
   «выталкиваются» на сферу), `checker` (шахматная доска из двух материалов), `obj` (загрузка OBJ-файла).
   Объекты масштабируются, поворачиваются (углы Эйлера) и сдвигаются. Для каждого треугольника запоминаем
   нормаль и номер материала.
3. **Построение ускоряющей структуры**: своя BVH по SAH (`accel.py`, ~1 с на 24 тыс. треугольников) или Embree (~0.02 с).
4. **Генерация первичных лучей**: для каждого из `spp` проходов — для каждого пикселя случайная точка в своей подклетке пикселя → луч из камеры.
5. **Трассировка** (`trace` в `render.py`), для каждой глубины:
   1. найти ближайшее пересечение всех текущих лучей (BVH/Embree);
   2. промахнувшиеся лучи получают яркость фона;
   3. в точке попадания: нормаль (сглаженная), материал, с какой стороны пришёл луч (снаружи/изнутри);
   4. **прямое освещение**: для каждого источника — направление, расстояние, освещённость
      `E = I0·cos θ_ист / R²` (или `E0` для параллельного); **теневой луч** к источнику (начало чуть сдвинуто
      по нормали на `eps`, чтобы не попасть в собственную поверхность — «теневые прыщи»/shadow acne); если не закрыт —
      добавляем `(kd/π + f_spec)·E·cos θ`;
   5. **вторичные лучи**: отражённый с весом `kr`, преломлённый с весом `kt` (при ПВО — всё в отражение);
      вес луча = произведение коэффициентов по пути; слишком слабые лучи (вес < 1e-4) отбрасываем.
6. **Усреднение** по `spp` проходам → изображение в абсолютных яркостях.
7. **Тональное отображение**: нормировка (`max`/`mean`/`fixed`) → отсечение > 1 → гамма 1/2.2 → 0..255.
8. **Запись** `output/<имя>.ppm` (+ `.png` и `_abs.npy` с абсолютными яркостями).
9. **Проверка корректности** (`verify.py`).

## 4. Почему результат правильный (доказательство корректности)

1. **Сравнение с формулой.** Плоскость (kd = 0.5) под ламбертовским точечным источником (I0 = 10 Вт/ср, высота h = 2).
   Аналитически: `L = kd/π · I0·cos θ · cos θ / r² = kd·I0·h² / (π·r⁴)` (оба косинуса равны h/r).
   Трассировщик в 7 точках даёт то же самое с относительной ошибкой ~1e-16 (машинная точность).
   То же для параллельного источника с бликом Блинна–Фонга.
2. **Три способа поиска пересечений совпадают**: перебор всех треугольников (заведомо правильный, но медленный),
   своя BVH и Embree находят **один и тот же** ближайший треугольник для 99.9 % лучей; все остальные расхождения —
   лучи, у которых **одинаковое** расстояние `t` до двух **совпадающих граней** (нижняя грань бокса лежит
   в плоскости пола) — оба ответа верны. Тени (`occluded`) совпадают на 100 %.
3. **Тени проверены аналитически**: для 3912 точек плоскости независимо (без треугольников, через пересечение
   отрезка «точка–источник» с повёрнутым кубом) определили, в тени ли точка. 0 несовпадений со всеми тремя бэкендами.
   Плюс на картинку нанесён аналитический контур тени (проекция вершин куба из источника на плоскость) — он
   совпадает с границей тени.
4. **Законы оптики**: `n1·sin θ1 = n2·sin θ2` выполняется до 8 знаков; угол отражения = углу падения;
   ПВО появляется ровно после критического угла 41.81°; луч, прошедший через плоскопараллельную стеклянную
   пластину, выходит **параллельно** входящему (отклонение 0°) со смещением — как в учебнике физики.
5. **Нормировка**: при `mean` средняя яркость Y после деления ровно 0.5; при `max` максимум ровно 1.
6. **Энергия**: у всех материалов сумма коэффициентов ≤ 1.

## 5. Вопросы, которые могут задать, и короткие ответы

* **Чем трассировка лучей отличается от растеризации?** Растеризация проецирует треугольники на экран (объект → пиксели), трассировка идёт от пикселя к объектам (пиксель → объект). Трассировка естественно даёт тени, отражения, преломления.
* **Почему трассировка «обратная»?** Реальный свет идёт от источника к глазу; мы идём от глаза к источнику, т.к. нас интересуют только лучи, попавшие в камеру. Это возможно благодаря закону обратимости световых лучей.
* **Как определяется тень?** Теневой луч из точки к источнику; если на отрезке есть пересечение ближе источника — точка в тени.
* **Зачем сдвигать начало вторичного/теневого луча (eps)?** Из-за погрешности float точка попадания может оказаться чуть «под» поверхностью, и луч пересечёт свою же поверхность → чёрные точки (shadow acne).
* **Почему стеклянный шар отбрасывает тень?** При обратной трассировке теневой луч прямой, а через стекло свет идёт по ломаной — найти путь «точка → стекло → точечный источник» невозможно (это каустика, её даёт только прямая/двунаправленная трассировка или фотонные карты). Поэтому прозрачные объекты для теневых лучей непрозрачны — это корректно в рамках локального освещения.
* **Почему точечный источник не виден в зеркале?** У него нулевая площадь: вероятность попасть в точку отражённым лучом равна нулю. Блик от источника на зеркальном/стеклянном объекте дают модели Фонга/Блинна–Фонга.
* **Чем отличаются Фонг и Блинн–Фонг?** Фонг: (R·V)^n — угол между отражённым лучом и направлением на наблюдателя. Блинн: (N·H)^n — угол между нормалью и полувектором. Блинн дешевле и на скользящих углах реалистичнее, блик шире при том же n.
* **Почему kd делим на π?** Чтобы отражённая светимость не превышала падающую освещённость: ∫ cos θ dω по полусфере = π, поэтому M = kd·E.
* **Что такое SAH и почему не делить просто пополам?** Медианное деление пополам не учитывает размеры коробок: может получиться огромная пустая коробка, в которую лучи будут попадать зря. SAH минимизирует ожидаемую стоимость обхода, используя то, что вероятность попадания луча в коробку ∝ её площади.
* **Какая сложность?** Перебор O(N) на луч, BVH ≈ O(log N) на луч, построение BVH по SAH O(N log² N) у нас (сортировки на каждом уровне).
* **Зачем Embree, если есть своя BVH?** Это требование задания (готовая библиотека) и эталон: она даёт те же ответы и строит структуру в ~40 раз быстрее (SIMD + многопоточность + оптимизированные алгоритмы на C++).
* **Что такое spp и стратификация?** Samples per pixel — лучей на пиксель. Стратификация: пиксель делится на подклетки, по лучу в каждую, — шум меньше, чем при полностью случайных точках.
* **Зачем гамма-коррекция?** Монитор нелинеен (выдаёт ≈ V^2.2), и глаз нелинеен. Без коррекции изображение будет слишком тёмным в тенях.
* **Что будет без нормировки?** Абсолютные яркости могут быть 0.001 или 1000 — нужно перевести в диапазон 0..1. Выбор нормировки — как «выдержка» фотоаппарата.
* **Почему всё, что > 1, отсекается?** Монитор не может показать ярче своего белого; это пересвет (как на фото).
* **Что такое трассировка путей в отличие от трассировки лучей?** В режиме `path` на каждой вершине пути случайно выбирается одно продолжение (отражение / преломление / обрыв — «русская рулетка») с вероятностью p, а вес делится на p. Матожидание то же, что и при ветвлении (`split`), но число лучей не растёт. Чем больше spp — тем меньше шум.

## 8. Производительность (таблица из отчёта)

| Сцена (треуг.) | Перебор, 12 потоков | Своя BVH, 1 поток | Своя BVH, 12 потоков | Embree, 1 поток |
|---|---|---|---|---|
| room (24 342) | 0.057 млн лучей/с | 4.71 | 32.5 | 8.71 |
| outdoor (29 740) | 0.045 | 4.59 | 24.9 | 9.19 |
| Построение структуры | — | ~1 с | ~1 с | ~0.026 с |

Как это объяснить:
* BVH быстрее перебора в **500–570 раз** при равном числе потоков. Это и есть смысл ускоряющей структуры.
* **Embree** в одном потоке примерно **в 2 раза быстрее** нашей BVH и строит дерево **почти в 40 раз быстрее**: она на C++,
  использует SIMD (проверяет 4–8 коробок одной инструкцией), хитрые эвристики построения.
* Почему тогда в таблице наша BVH на 12 потоках быстрее Embree? Python-обёртка `embreex` вызывает Embree для лучей
  **по одному и в одном потоке** (проверили: процессорное время = реальному времени). Наш код на `numba` раскидывает
  лучи по 12 ядрам. Если вызывать Embree из C++ пакетами и многопоточно — она будет быстрее.
* Полный рендер комнаты 600×600×4: 3.5 с (BVH) и 3.7 с (Embree) — больше всего времени уходит не на пересечения,
  а на расчёт освещения в `numpy`.

| Где трассировка путей (рекурсия)? | `render.py` → `trace` (цикл по глубине, режимы `split`/`path`) |
| Где нормировка и гамма? | `render.py` → `normalization`, `tone_map` |
| Где запись PPM? | `render.py` → `save_ppm` |
| Где команды интерфейса? | `main.py` → `App.execute` |

Про стиль кода: «рекурсия» сделана не рекурсивными вызовами, а **волнами**: все лучи одной глубины обрабатываются
одним массивом `numpy` (так в сотни раз быстрее в Python). Массив `idx` хранит, к какому пикселю относится луч,
`weight` — произведение коэффициентов `kr`/`kt` вдоль пути. Это эквивалентно рекурсии
`L = local + kr·L(отражённый) + kt·L(преломлённый)`.

## 11. Что мы НЕ учитываем (честно, если спросят)

* **Глобальное освещение** (диффузные переотражения, «цветные отсветы» от стен) — в задании только локальное освещение.
* **Каустики** (свет, сфокусированный стеклом) — обратной трассировкой от точечного источника их не получить.
* **Формулы Френеля** — коэффициенты отражения/пропускания у стекла постоянные (заданы в материале), а в реальности
  отражение растёт к скользящим углам. Можно добавить приближением Шлика.
* **Поглощение в среде** (закон Бугера) — среды прозрачные, без поглощения, как и сказано в задании.
* **Вложенные среды** — считаем, что снаружи тела всегда воздух (n = 1).
* **Спектр** — модель RGB (задание это разрешает), дисперсии (радуги в призме) нет.

## 12. Мини-шпаргалка формул

```
Луч:                    p(t) = o + t·d
Камера:                 d = normalize(f + x·r + y·u),  x = (2px/W − 1)·tan(fov/2)·W/H,  y = (1 − 2py/H)·tan(fov/2)
Мёллер–Трумбор:         P = d×e2, det = e1·P, u = (s·P)/det, Q = s×e1, v = (d·Q)/det, t = (e2·Q)/det
Slab-тест:              t1,2 = (min,max − o)/d;  tn = max(min(t1,t2)), tf = min(max(t1,t2));  попал, если tn ≤ tf, tf ≥ 0
SAH:                    C = 1 + (S_L/S)·N_L + (S_R/S)·N_R;  лист, если C ≥ N
Источник Ламберта:      I(θ) = I0·cos θ
Освещённость:           E = I(θ)·cos θ_пов / R²       (параллельный: E = E0·cos θ)
Ламберт:                f = kd/π
Фонг:                   f = ks·(n+2)/(2π)·(R·V)^n,   R = 2(N·L)N − L
Блинн–Фонг:             f = ks·(n+8)/(8π)·(N·H)^n,   H = normalize(L + V)
Яркость точки:          L = Σ (kd/π + f_s)·E_j·V_j + kr·L_отр + kt·L_прел
Отражение:              R = D − 2(D·N)N
Преломление (Снеллиус): n1 sin θ1 = n2 sin θ2;  k = 1 − η²(1 − cos²θ1);  T = ηD + (η cos θ1 − √k)N;  k < 0 → ПВО
Критический угол:       θкр = arcsin(n2/n1) = 41.8° для стекла
Нормировка:             V = min(1, L / L_norm);   L_norm = max | mean(Y)/0.5 | заданное
Гамма:                  V_corr = V^(1/2.2);   байт = round(255·V_corr)
Яркость Y:              0.2126 R + 0.7152 G + 0.0722 B
```

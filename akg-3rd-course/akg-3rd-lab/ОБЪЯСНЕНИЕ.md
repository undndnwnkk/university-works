# ЛР-4 по АКГ простыми словами: «построение спектра по цвету»

## 1. Что вообще происходит

На сцене стоит **сфера**, её освещают **два точечных источника света**, сверху смотрит **наблюдатель (камера)**.
Мы считаем, какой яркости и какого цвета будет каждая точка сферы на картинке.

В ЛР-3 сцена была **спектральной**: у каждого источника был спектр (сколько энергии он излучает на каждой
длине волны от 380 до 780 нм), у сферы — спектральный коэффициент отражения. Из этого получали картинку.

В ЛР-4 задача обратная. Представим, что спектров у нас **нет**, а есть только **цвета в RGB**
(так обычно и бывает: дизайнер выбрал цвет лампы в палитре). Нужно:

1. **По RGB-цвету придумать спектр**, который даёт именно этот цвет (это и есть «построение спектра по цвету»).
2. С этими спектрами **отрендерить сферу спектрально** и получить картинку `image_A`.
3. **Сравнить** придуманные спектры с настоящими (из ЛР-3) — пункт B.
4. **Сравнить** картинку `image_A` с картинками ЛР-3 `image_1` и `image_2` — пункт C.

Цепочка пункта A в задании:

```
RGB-сцена ─► спектры (восстановленные) ─► спектральное изображение L(x,y,λ)
          ─► XYZ ─► RGB (абсолютные числа) ─► RGB 0..255 ─► файл image_A.png
```

Так как кода ЛР-3 в папке нет, программа сама строит и «исходную» спектральную сцену ЛР-3,
и её картинки:

* `image_1` — спектральный расчёт с настоящими спектрами (эталон);
* `image_2` — расчёт сразу в RGB (три канала вместо 41 длины волны).

## 2. Основные термины

| Термин | Простыми словами |
|---|---|
| **Спектр S(λ)** | Таблица «длина волны → сколько энергии». У нас 41 число: 380, 390, …, 780 нм. |
| **Спектрограмма** | То же, что спектр, но заданный таблицей (как в задании). |
| **Цвет** | То, что видит глаз. Глаз «сжимает» спектр из 41 числа в 3 числа. |
| **CIE XYZ** | Стандартный способ описать цвет тремя числами. `X = Σ S(λ)·x̄(λ)·Δλ`, так же Y и Z. **Y — это яркость.** |
| **x̄, ȳ, z̄** | Функции цветового соответствия — «чувствительность» стандартного наблюдателя (таблица CIE 1931 в `cie_data.py`). |
| **CIE RGB** | Другие три числа для цвета. Связаны с XYZ матрицей 3×3 (`M_RGB_TO_XYZ`, `M_XYZ_TO_RGB`). |
| **D65** | Стандартный «дневной белый свет» (спектр-таблица). Относительно него задаётся «белизна» сферы. |
| **Источник A** | Лампа накаливания (абсолютно чёрное тело при 2856 K) — желтоватый свет. |
| **Закон Планка** | Формула спектра нагретого тела по температуре T. Используется для источника A и «Планка, T». |
| **Метамерия / метамеры** | Разные спектры, которые дают **одинаковый** цвет. Глаз их не различает. Поэтому спектр по цвету восстанавливается неоднозначно! |
| **Базисные функции F1, F2, F3** | Три «кирпичика», из которых собираем спектр: `S(λ) = a1·F1 + a2·F2 + a3·F3`. |
| **kd(λ)** | Коэффициент диффузного отражения: какую долю света каждой длины волны сфера отражает. Белая сфера: kd = 1 везде. |
| **Ламбертовский источник** | Светит сильнее всего вниз (по своей оси), вбок слабее: `I = I0·cos θ`. |
| **Ламбертовская поверхность** | Матовая: выглядит одинаково яркой с любой стороны. Яркость `L = kd·E/π`. |
| **Сила излучения I0** | Сколько ватт на стерадиан источник излучает по оси (Вт/ср). |
| **Освещённость E** | Сколько света падает на единицу площади: `E = I·cos σ / R²` (Вт/м²). Чем дальше источник и чем «косее» падает свет, тем меньше. |
| **Яркость L** | Что реально видит камера в точке. Энергетическая `Le` в Вт/(ср·м²), световая `Lv = 683·Y` в кд/м². |
| **Нормировка 0..255** | Делим все RGB на максимум по картинке и умножаем на 255 — чтобы показать на мониторе. |
| **Гамма-коррекция** | Нелинейное «осветление» `v^(1/2.2)` под особенности монитора (флажок, по умолчанию выключен). |
| **Баланс белого** | Точка белого CIE RGB — равноэнергетический свет E, поэтому D65 в ней голубоватый. Флажок делит каналы на RGB(D65), чтобы белое стало серым. |

## 3. Как именно восстанавливается спектр (главная идея лабы)

Из лекции 4: хотим спектр `S(λ) = a1·F1(λ) + a2·F2(λ) + a3·F3(λ)`, у которого цвет равен заданному.

1. Переводим RGB в XYZ: `X = M · RGB`.
2. Считаем цвет каждой базисной функции: столбец `j` матрицы `C` — это XYZ функции `Fj`.
3. Цвет суммы = сумма цветов (всё линейно), значит `X = C · a`, откуда **`a = C⁻¹ · X`**.

Три коэффициента — три уравнения — решение единственное. Но **форма** спектра зависит от того, какие
«кирпичики» мы выбрали, — поэтому в программе можно выбрать один из трёх базисов:

* **Прямоугольные полосы** (синяя 380–480, зелёная 490–580, красная 590–780 нм) — ступенька;
* **Гауссовы** (горбы на 450, 550, 610 нм) — гладко;
* **Дельта-функции** (по одной длине волны: 440, 550, 700 нм) — пример из лекции, даёт «разрывный» спектр.

**Для коэффициента отражения сферы** чуть хитрее: его RGB задан *относительно D65*
(`kd_RGB = R'/R, G'/G, B'/B`, где `R'G'B'` — цвет D65·kd, а `RGB` — цвет самого D65).
Поэтому ищем `kd(λ) = Σ bj·Fj(λ)` так, чтобы **цвет D65(λ)·kd(λ)** совпал с нужным —
в матрице `C` просто каждая базисная функция умножается на D65.

## 4. Что получилось (кратко)

* Цвет (XYZ) восстановленного спектра **всегда совпадает** с исходным, а форма — нет (метамер).
* Для **белой сферы и прямоугольного базиса** `image_A` практически совпадает с `image_1` и `image_2`
  (разница ≤ 1 уровня из 255): белый kd восстанавливается точно (= 1), а при постоянном kd цвет картинки
  зависит только от XYZ источников.
* **Гауссов** базис даёт волнистый kd(λ) → небольшая ошибка цвета (~4.5 %).
* **Дельта-функции** дают бессмыслицу (kd ≫ 1 на одной длине волны) — та самая «проблема метода» из лекции.
* У насыщенного синего источника восстановленный спектр уходит **в минус** — его цвет вне охвата CIE RGB.
* В методичке у обратной матрицы XYZ→RGB **потерян множитель 0.17697** (без него M·M⁻¹ = 5.65·E).
  В коде он добавлен.

## 6. Разбор главных строчек кода

### Цветовые преобразования (`lab4.py`)

```python
def spectrum_to_xyz(spectrum):
    return np.asarray(spectrum) @ CMF_XYZ * D_LAMBDA
```
Интеграл `∫ S(λ)·x̄(λ) dλ` превращается в сумму: умножаем вектор спектра (41 число) на матрицу
41×3 (столбцы x̄, ȳ, z̄) и на шаг 10 нм. Благодаря `@` та же строчка работает и для целого
изображения формы (H, W, 41) — получаем (H, W, 3).

```python
M_XYZ_TO_RGB = 0.17697 * np.array([...])
```
Обратная матрица из методички, домноженная на потерянный коэффициент.

### Спектры источников

```python
def normalized(spectrum):
    return spectrum / (spectrum.sum() * D_LAMBDA)
```
Делаем так, чтобы площадь под спектром была 1. Тогда `I0 · S(λ)` — это сколько Вт/ср приходится на
каждый нанометр, а суммарно ровно `I0`.

### Восстановление спектра

```python
def basis_matrix(basis, weight=None):
    f = basis if weight is None else basis * weight[:, None]
    return CMF_XYZ.T @ f * D_LAMBDA          # матрица C 3×3
```
Каждый столбец результата — XYZ одной базисной функции (для отражения — умноженной на D65).

```python
def reconstruct_light(rgb, basis):
    xyz = rgb_to_xyz(rgb)                               # X = M·RGB
    coeffs = np.linalg.solve(basis_matrix(basis), xyz)  # a = C⁻¹·X
    return basis @ coeffs, coeffs                       # S = Σ a_j F_j
```
Ровно формула из лекции. `np.linalg.solve` решает систему 3×3 (это точнее, чем явно обращать матрицу).

```python
def reconstruct_reflectance(kd_rgb, basis):
    target_rgb = kd_rgb * spectrum_to_rgb(D65_NORM)          # нужный цвет D65·kd
    coeffs = np.linalg.solve(basis_matrix(basis, weight=D65_NORM), rgb_to_xyz(target_rgb))
    return basis @ coeffs, coeffs
```

### Геометрия: куда попадает луч

```python
D = np.stack([X, Y, np.full_like(X, -scene.zO)], axis=-1)   # от глаза к пикселю (x, y, 0)
D /= np.linalg.norm(D, axis=-1, keepdims=True)
oc = scene.eye - scene.center
b = D @ oc
c = oc @ oc - scene.r ** 2
disc = b * b - c                    # дискриминант: < 0 — луч мимо сферы
t = -b - np.sqrt(...)               # ближайшая точка пересечения
P = scene.eye + t[..., None] * D    # точка на сфере
N = (P - scene.center) / scene.r    # нормаль
```
Для **всех пикселей сразу** (numpy, без циклов) решаем квадратное уравнение «луч ∩ сфера».

### Освещённость от одного источника

```python
s = P - (x_L, y_L, z_L)                  # от источника к точке
cos_theta = clip(-s_z / R, 0)            # угол с осью источника (ось смотрит вниз, O = (0,0,-1))
cos_sigma = clip(-(s·N) / R, 0)          # угол падения света на поверхность
G = cos_theta * cos_sigma / (R/1000)**2  # мм → м
```
`E = I0 · G`. Если косинус отрицательный (свет сзади поверхности или источник светит «не туда») —
обнуляем: точка в тени.

### Спектральное изображение

```python
E = weights @ light_spectra        # (H,W,2) @ (2,41) → (H,W,41): Σ I0_i·G_i·S_i(λ)
L = E * kd / np.pi                 # яркость ламбертовской поверхности
```
Это и есть «спектральное изображение в памяти в абсолютных единицах»: для каждого пикселя 41 число
в Вт/(ср·м²·нм).

```python
rgb_A = xyz_to_rgb(spectrum_to_xyz(spectral_A))   # → RGB в абсолютных единицах

```

## 7. Что спросят на защите (шпаргалка)

* **Почему спектр по цвету восстанавливается неоднозначно?** Глаз (и XYZ) сжимает 41 число до 3;
  бесконечно много спектров дают один цвет (метамерия). Выбор базиса = выбор одного из метамеров.
* **Почему восстановленный спектр бывает отрицательным?** Цвет вне охвата базиса (насыщенные цвета),
  коэффициенты `a` получаются со знаком минус.
* **Почему для белой сферы image_A ≈ image_1?** При kd = const яркость в каждой точке — линейная
  комбинация спектров источников, а значит её цвет — та же комбинация их XYZ. XYZ мы сохраняем точно.
* **Почему image_1 ≠ image_2 для цветной сферы?** Цвет произведения спектров ≠ произведению цветов:
  покомпонентное умножение RGB — лишь приближение.
* **Зачем делить на π?** Для ламбертовской поверхности связь яркости и освещённости `L = kd·E/π`.
* **Почему min яркости = 0?** Часть видимой поверхности сферы не освещена ни одним источником
  (собственная тень).

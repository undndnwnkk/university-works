# Объяснение лабораторной №3 простым языком

## Что вообще сделано (в двух словах)

Есть таблица про 10 000 студентов: сколько часов учился, какие были прошлые
оценки, сколько спит, сколько пробных вариантов прорешал, ходит ли на кружки.
И есть итоговый балл `Performance Index` (от 10 до 100).

Задача — найти **формулу**, которая по этим пяти числам предсказывает балл:

```
балл ≈ b0 + b1·часы + b2·прошлые_оценки + b3·кружки + b4·сон + b5·варианты
```

Числа `b0 … b5` (коэффициенты) мы не придумываем, а **вычисляем** по данным
методом наименьших квадратов (МНК) — так, чтобы формула ошибалась как можно
меньше. Потом проверяем, насколько хорошо формула работает на студентах,
которых она «не видела» (тестовая выборка), с помощью метрики R².

Делаем это для трёх разных наборов признаков и сравниваем — так узнаём,
какие признаки реально важны.

Итоговая формула (модель 1):

```
балл = −33.92 + 2.85·часы + 1.018·прошлые + 0.62·кружки + 0.47·сон + 0.19·варианты
```

Читается так: +1 час учёбы → +2.85 балла; +1 балл на прошлых экзаменах →
+1.02 балла; ходит на кружки → +0.62 балла и т. д.

## Основные определения

**Регрессия** — задача предсказать *число* (балл, цену, температуру) по
другим числам. В отличие от классификации, где предсказываем *класс*
(«сдал / не сдал»).

**Признак (фактор, независимая переменная, x)** — то, по чему предсказываем:
часы учёбы, сон и т. д.

**Целевая переменная (зависимая переменная, отклик, y)** — то, что
предсказываем: `Performance Index`.

**Линейная регрессия** — модель вида `ŷ = b0 + b1·x1 + … + bp·xp`.
«Линейная» — потому что каждый признак входит с весом и всё просто
складывается. Множественная — когда признаков больше одного.

**Коэффициенты (веса) b1…bp** — насколько изменится ŷ, если признак
вырастет на 1, а остальные не меняются.

**Свободный член (intercept, b0)** — значение ŷ, когда все признаки
равны 0. Часто не имеет смысла (в нашем случае −33.9 — студент с нулевыми
прошлыми оценками, которых не бывает, шкала начинается с 40).

**Остаток (ошибка) eᵢ = yᵢ − ŷᵢ** — насколько ошиблись на i-м студенте.

**МНК (метод наименьших квадратов)** — выбираем коэффициенты так, чтобы
сумма квадратов остатков `Q = Σ(yᵢ − ŷᵢ)²` была минимальна.

**Нормальные уравнения** — система `(XᵀX)·B = XᵀY`, которая получается,
если взять производную Q по коэффициентам и приравнять к нулю. Её решение
и есть коэффициенты МНК.

**Матрица X (design matrix)** — таблица признаков, к которой слева
приписан столбец из единиц. Единицы нужны, чтобы свободный член b0
считался как обычный коэффициент (`b0·1`).

**Метод Гаусса** — школьный способ решать систему линейных уравнений:
приводим к треугольному виду (прямой ход), потом находим неизвестные снизу
вверх (обратный ход). **Выбор главного элемента** — на каждом шаге ставим
наверх строку с самым большим по модулю элементом в столбце, чтобы не
делить на 0 и на очень маленькие числа (меньше ошибок округления).

**R² (коэффициент детерминации)** — `R² = 1 − SS_res / SS_tot`, где
`SS_res = Σ(yᵢ − ŷᵢ)²` (ошибка модели), `SS_tot = Σ(yᵢ − ȳ)²` (ошибка
«тупой» модели, которая всегда говорит среднее). Смысл: **какую долю
разброса y объясняет модель**. 1 — идеально, 0 — не лучше среднего,
< 0 — хуже среднего.

**Скорректированный R² (adjusted R²)** — R² со штрафом за количество
признаков: `1 − (1 − R²)(n − 1)/(n − p − 1)`. Обычный R² не уменьшается
при добавлении любого мусорного признака, а скорректированный может
уменьшиться.

**RMSE** — корень из среднего квадрата ошибки, `√(Σ(yᵢ − ŷᵢ)²/n)`. Это
«типичная ошибка в баллах». У нас ≈ 2 балла.

**Обучающая / тестовая выборка (train / test)** — на train подбираем
коэффициенты, на test проверяем. Тест нужен, чтобы оценить, как модель
работает на новых данных, а не на тех, которые она уже «видела».

**Переобучение** — модель отлично работает на train и плохо на test
(запомнила шум). Признак: R² train ≫ R² test. У нас разница < 0.01, значит
переобучения нет.

**Нормировка (стандартизация, z-score)** — `z = (x − среднее) / std`.
После неё у признака среднее 0 и стандартное отклонение 1.

**Утечка данных (data leakage)** — когда информация из теста попадает в
обучение. Поэтому среднее и std для нормировки считаем **только по train**.

**Категориальный признак** — значения не числа, а категории (Yes/No).
**Кодирование** — превращение категорий в числа. У нас бинарное: No → 0,
Yes → 1. **One-hot** — по столбцу на каждую категорию (для двух категорий
с удалением одного столбца это то же самое).

**Корреляция Пирсона r** — число от −1 до 1, насколько линейно связаны
две величины. Для однофакторной регрессии `R² = r²`.

**Мультиколлинеарность** — когда признаки сильно коррелируют между собой.
Тогда XᵀX почти вырождена, коэффициенты нестабильны. У нас её нет
(|r| между признаками < 0.03).

**Синтетический признак** — новый признак, вычисленный из имеющихся.
У нас `Hours_x_Previous = Hours · Previous` (взаимодействие) и
`Hours_sq = Hours²` (квадрат, для нелинейности).

**Статистика из задания:**
- *count* — число значений;
- *mean* — среднее арифметическое;
- *std* — стандартное отклонение, «насколько в среднем значения
  отклоняются от среднего»;
- *min / max* — минимум / максимум;
- *квантиль q%* — значение, меньше которого q% данных. 25% — первый
  квартиль Q1, 50% — медиана, 75% — третий квартиль Q3.

## Как работает МНК (главный вопрос)

### Вывод формулы

Хотим минимизировать `Q(B) = Σ(yᵢ − ŷᵢ)² = (Y − XB)ᵀ(Y − XB)`.

Раскрываем: `Q = YᵀY − 2BᵀXᵀY + BᵀXᵀXB`.

Производная по B: `∂Q/∂B = −2XᵀY + 2XᵀXB`.

Приравниваем к нулю → `XᵀX·B = XᵀY` → `B = (XᵀX)⁻¹XᵀY`.

Это минимум, а не максимум, потому что XᵀX положительно определена
(Q — «чаша», парабола вверх).

### Как это в коде (`linreg.py`)

```python
def fit(self, x, y):
    xd = self._design(x)                       # приклеили столбец единиц
    beta = solve_gauss(xd.T @ xd, xd.T @ y)    # решили (XᵀX)B = XᵀY
    self.intercept_ = beta[0]                  # b0
    self.coef_ = beta[1:]                      # b1..bp
```

Матрицу `(XᵀX)⁻¹` **не обращаем**, а решаем систему методом Гаусса
(`solve_gauss`). Результат тот же, но это быстрее и точнее.

Размеры: X — 7898×6 (5 признаков + единицы), XᵀX — 6×6, XᵀY — вектор
из 6 чисел. То есть решаем систему всего из 6 уравнений.

### `solve_gauss` по шагам

1. Склеиваем A и b в расширенную матрицу `[A | b]`.
2. Прямой ход: для каждого столбца `col`
   - ищем строку с максимальным |элементом| в этом столбце (ниже
     диагонали) и меняем её местами с текущей — это выбор главного
     элемента;
   - если максимум ≈ 0 — матрица вырождена, бросаем ошибку;
   - вычитаем текущую строку из всех нижних, чтобы под диагональю
     получились нули.
3. Обратный ход: с последней строки находим `x[row] = (b − сумма известных) / диагональ`.

### Почему нормируем признаки

- Признаки в разных шкалах: часы 1–9, оценки 40–99. После нормировки
  коэффициенты **сравнимы** между собой: β показывает, на сколько баллов
  меняется результат, если признак вырос на одно стандартное отклонение.
  Поэтому по нормированным β видно, что Previous (17.7) важнее Hours (7.4).
- Числа в XᵀX одного порядка → метод Гаусса считает точнее.

На R² нормировка **не влияет** — линейная модель просто пересчитывает
коэффициенты. Чтобы получить «человеческую» формулу, коэффициенты
переводятся обратно (`destandardize`): `b = β / std`,
`b0 = β0 − Σ b·mean`.

### Проверка, что всё правильно (`test_linreg.py`)

- пример из методички (накопления по доходу и имуществу) — получаем
  ровно `0.2787 + 0.1229·Y − 0.0294·W`;
- на данных без шума коэффициенты восстанавливаются точно, R² = 1;
- на зашумлённых данных совпадает с `np.linalg.lstsq` (эталон используется
  **только в тестах**, в самой регрессии его нет);
- метод Гаусса совпадает с `np.linalg.solve`, работает с нулём на диагонали,
  ругается на вырожденную матрицу.

## Что получилось

| Модель | Признаки | R² test | RMSE |
|---|---|---|---|
| 1 | все 5 | **0.9885** | 2.05 |
| 2 | Hours + Previous | 0.9851 | 2.33 |
| 3 | всё, кроме Previous | 0.1371 | 17.74 |
| 4 (бонус) | все + Hours·Previous + Hours² | 0.9885 | 2.05 |

Однофакторные модели (каждый признак отдельно): Previous 0.834,
Hours·Previous 0.514, Hours 0.137, остальные ≈ 0.

**Почему модели выбраны именно такие:**
- модель 1 — полный набор, эталон;
- модель 2 — только два самых сильных признака: проверяем, можно ли
  упростить модель почти без потери качества (можно: 0.985 против 0.989);
- модель 3 — убрали самый сильный признак: проверяем, насколько он
  незаменим (очень: R² падает до 0.14).

**Главные выводы:**
1. Прошлые оценки — лучший предиктор (один даёт R² = 0.83).
2. Часы учёбы — второй по важности.
3. Сон, варианты, кружки поодиночке почти бесполезны (R² ≈ 0), но в полной
   модели немного улучшают её (RMSE 2.33 → 2.05). Их влияние малое, но
   не нулевое.
4. Переобучения нет.
5. Синтетические признаки не помогли → зависимость чисто линейная и
   аддитивная (датасет, судя по всему, сгенерирован именно линейной формулой
   с шумом).

## Заготовленные ответы на вероятные вопросы

**— Что такое линейная регрессия?**
Модель, которая предсказывает число как взвешенную сумму признаков плюс
константа: `ŷ = b0 + b1x1 + … + bpxp`.

**— Что такое МНК и почему именно квадраты?**
Подбираем коэффициенты, минимизируя сумму квадратов ошибок. Квадрат:
(1) убирает знак, ошибки +5 и −5 не компенсируют друг друга;
(2) функция гладкая, её можно продифференцировать и получить решение
формулой; (3) сильнее штрафует большие ошибки. Модуль не дифференцируем
в нуле, формулы для него нет.

**— Выведите формулу коэффициентов.**
См. раздел «Вывод формулы»: производная `−2XᵀY + 2XᵀXB = 0` →
`B = (XᵀX)⁻¹XᵀY`.

**— Зачем столбец единиц в X?**
Чтобы свободный член b0 считался как обычный коэффициент, без отдельной
формулы. Без него прямая обязана проходить через ноль.

**— Почему вы не обращаете матрицу?**
Решить систему методом Гаусса дешевле и точнее, чем найти обратную матрицу
и умножить. Обращение — это фактически решение n систем вместо одной.

**— Что будет, если XᵀX вырождена?**
Решения не единственны — бесконечно много наборов коэффициентов дают ту же
ошибку. Так бывает, если признаки линейно зависимы (например, один признак
— сумма двух других, или one-hot без удаления столбца, или признаков
больше, чем строк). Мой `solve_gauss` в этом случае бросает ошибку.
Лечится удалением лишнего признака или регуляризацией (Ridge:
`(XᵀX + λI)B = XᵀY`).

**— Вы использовали библиотеки?**
NumPy — только для хранения массивов и умножения матриц (`@`), Pandas — для
чтения CSV и статистики, matplotlib — для графиков. Коэффициенты считаю
сам: свой метод Гаусса, без `np.linalg`, без sklearn. `np.linalg` есть
только в тестах — как эталон для сравнения.

**— Что такое R²? Как интерпретировать 0.9885?**
Доля дисперсии y, объяснённая моделью. 0.9885 → модель объясняет 98.85 %
разброса баллов, необъяснённым остаётся 1.15 %.

**— Может ли R² быть отрицательным?**
На обучающей выборке с константой — нет (МНК не может быть хуже среднего,
среднее — частный случай модели). На тестовой — может, если модель хуже,
чем просто предсказывать среднее. У нас однофакторные модели по Papers и
Extracurricular дали на тесте −0.0006 и −0.0046 — признак бесполезен,
а модель на нём чуть-чуть подстроилась под шум train.

**— Может ли R² быть больше 1?**
Нет, SS_res ≥ 0.

**— Чем R² отличается от adjusted R²?**
Обычный R² никогда не уменьшается при добавлении признака, даже
случайного. Adjusted штрафует за число признаков и растёт, только если
признак реально полезен. У нас n = 1975 большое, поэтому они почти
совпадают.

**— Почему R² test может быть чуть меньше R² train?**
На train коэффициенты подобраны именно под эти данные, на test — новые
данные. Небольшая разница (у нас < 0.01) — норма; большая — переобучение.

**— Зачем делить на train и test?**
Чтобы честно оценить качество на новых данных. Если оценивать на тех же
данных, на которых обучали, результат будет завышен.

**— Почему 80/20? Что такое seed?**
80/20 — стандартная пропорция: достаточно данных для обучения и
достаточно для надёжной оценки (1975 строк). Seed = 42 — начальное
значение генератора случайных чисел, чтобы разбиение было одинаковым при
каждом запуске (воспроизводимость).

**— Зачем перемешивать перед разбиением?**
Если данные отсортированы (например, по баллу), без перемешивания в test
попадут только отличники — оценка будет нечестной.

**— Зачем нормировка, если на R² она не влияет?**
(1) Нормированные коэффициенты сравнимы между собой — видно, какой признак
важнее. (2) Численная устойчивость решения. (3) Для градиентного спуска и
регуляризации она обязательна (здесь нет, но это общая практика).

**— Почему среднее и std только по train?**
Чтобы не было утечки данных: в реальности будущих данных мы не знаем,
значит и их статистику использовать нельзя. Тестовые данные преобразуются
теми же параметрами, что и train.

**— Как обработали пропуски?**
Их нет (проверено `isna().sum()` = 0). В коде предусмотрено: числовые
пропуски → медиана (устойчива к выбросам, в отличие от среднего),
категориальные → мода (самое частое значение). Альтернативы: удалить
строки, если пропусков мало.

**— Зачем удалили дубликаты?**
127 полностью одинаковых строк. Одна копия могла попасть в train, другая
в test — тогда модель «видела» тестовый пример, и оценка завышена.

**— Как закодировали категориальный признак? Почему не one-hot?**
No → 0, Yes → 1. При двух категориях one-hot даёт два столбца
`is_yes` и `is_no`, которые в сумме = 1 = столбцу единиц → XᵀX вырождена
(«ловушка фиктивных переменных»). Поэтому один столбец удаляют — и остаётся
ровно наш бинарный признак.

**— Как интерпретировать коэффициенты?**
В исходных единицах: при прочих равных +1 час учёбы → +2.85 балла,
+1 балл прошлых оценок → +1.02, кружки → +0.62, +1 час сна → +0.47,
+1 вариант → +0.19. Нормированные: на сколько баллов меняется результат
при росте признака на одно стандартное отклонение — по ним сравниваем
важность.

**— Почему свободный член −33.9, балл же не бывает отрицательным?**
Это значение при всех признаках = 0, а такого студента не бывает
(Previous ≥ 40, Sleep ≥ 4). Это просто «сдвиг» прямой, вне диапазона
данных он не имеет смысла.

**— Почему у моделей 1 и 2 коэффициенты при Hours и Previous почти
одинаковые?**
Признаки между собой не коррелируют. Поэтому выкидывание Sleep, Papers и
Extracurricular не смещает оценки остальных — их вклад просто уходит в
ошибку. Если бы признаки коррелировали, коэффициенты бы заметно поменялись.

**— Почему модель 3 такая плохая?**
Убрали Previous, а он один объясняет 83 % дисперсии. Оставшиеся признаки
объясняют только ≈ 14 %, почти всё — Hours. На графике прогноз против факта
у модели 3 «облако»: модель не различает сильных и слабых студентов и
предсказывает всем 40–70.

**— Какие признаки работают лучше всего?**
Previous ≫ Hours ≫ Sleep ≈ Papers ≈ Extracurricular. Определяем тремя
способами: корреляция с целевой (0.92, 0.38, ~0.05), R² однофакторных
моделей (0.83, 0.14, ~0), нормированные коэффициенты (17.7, 7.4, < 1).

**— Если Sleep, Papers, Extracurricular такие слабые, зачем они?**
Поодиночке R² ≈ 0, но в полной модели они снижают RMSE с 2.33 до 2.05 и
поднимают R² на 0.34 п.п. Эффект маленький, но настоящий: остальная
дисперсия у y уже объяснена, и их небольшой вклад становится заметен.
Если нужна простая модель — хватит модели 2.

**— Что за синтетический признак и почему он не помог?**
`Hours·Previous` (взаимодействие — «час учёбы полезнее сильному студенту»)
и `Hours²` (нелинейность — «убывающая отдача от учёбы»). Сам по себе
Hours·Previous информативен (R² = 0.51), потому что содержит Previous. Но
в полной модели его коэффициент ≈ 0 и R² не меняется — значит, в данных нет
ни взаимодействия, ни нелинейности, всё уже описано линейной моделью.
На данных с нелинейной зависимостью такие признаки дали бы прирост.

**— Почему R² однофакторной модели = квадрат корреляции?**
Для одного признака МНК-прямая даёт `R² = r²` — это известное свойство
парной регрессии. Проверка: r(Previous) = 0.915, 0.915² ≈ 0.837 ≈ 0.834
(разница — потому что R² посчитан на тесте, а r — на всех данных).

**— Есть ли переобучение?**
Нет: R² train и test отличаются меньше чем на 0.01. У линейной модели
с 5 признаками на 7898 примерах просто нет «ёмкости», чтобы запомнить шум.

**— Какие предположения у линейной регрессии? Выполняются ли они?**
1. Линейность зависимости — да, синтетические признаки ничего не добавили.
2. Независимость наблюдений — разные студенты, считаем да.
3. Гомоскедастичность (одинаковый разброс ошибок) — по графику прогноз/факт
   ширина облака примерно одинаковая.
4. Нормальность остатков — гистограмма остатков колоколообразная,
   симметрична вокруг 0.
5. Нет мультиколлинеарности — |r| между признаками < 0.03.

**— Как ещё можно найти коэффициенты, кроме нормальных уравнений?**
Градиентным спуском: начинаем со случайных весов и шагаем против
градиента Q. Нужен, когда признаков очень много (обращать/решать огромную
систему p×p дорого — O(p³)). При малом p, как у нас, нормальные уравнения
быстрее и дают точный ответ.

**— Какая сложность вашего метода?**
Посчитать XᵀX — O(n·p²), решить систему Гауссом — O(p³). n = 7898, p = 6
— мгновенно.

**— Что такое скалярный метод из методички?**
Те же нормальные уравнения, только записанные суммами
(`a·n + b1·Σx1 + … = Σy` и т. д.). Матрица этой системы — ровно XᵀX.
Я решаю её в матричном виде, но методом Гаусса — то же самое.

**— Что показывают квантили и ящик с усами?**
Квантили описывают распределение: медиана — середина, Q1–Q3 — где лежит
средняя половина данных. На ящике: коробка от Q1 до Q3, линия — медиана,
усы — минимум и максимум. Выбросов нет, все значения в разумных пределах.

**— Как улучшить модель?**
На этих данных — почти никак: R² = 0.989, остаток похож на случайный шум.
В общем случае: добавить новые признаки, нелинейные преобразования,
регуляризацию (Ridge/Lasso), кросс-валидацию вместо одного разбиения.

**— Что такое кросс-валидация?**
Делим данные на k частей, k раз обучаем на k−1 частях и тестируем на
оставшейся, усредняем R². Оценка надёжнее, чем от одного случайного
разбиения. Здесь не требовалась, но разброс между train и test у нас и так
маленький.
